# Privault `.pvault` 加密导入导出设计

日期：2026-11-01  
状态：设计已获用户认可，待实现

## 1. 目标与范围

在现有目录迁移基础上，增加跨设备 `.pvault` 单文件导入导出：

- 导出整个加密保险库为单个 `.pvault` 文件。
- 导入时先验证原保险库主密码，再备份当前库并原子替换。
- 导入后保留原保险库的主密码、恢复密钥、条目、收藏和密码历史。

不包含：自动同步、条目级合并、冲突解决、覆盖已有导出文件、明文导出、云传输或 Windows 实测声明。

## 2. 文件格式与加密边界

`.pvault` 使用 ZIP 容器，包含且只允许以下三个条目：

```text
vault.db
vault.meta
manifest.json
```

- `vault.db`：SQLCipher 加密数据库，保持原字节内容。
- `vault.meta`：原 KDF 参数、盐值、Nonce 和双密钥槽，保持原字节内容。
- `manifest.json`：仅 `formatVersion: 1` 和 `createdAt`，不包含源绝对路径、主密码、恢复密钥、条目或设备秘密。

ZIP 容器本身不重复加密；内部数据仍是 SQLCipher 密文。密码和 DEK 不会写入容器、日志或临时明文文件。`config.json` 不导出，因为其中路径具有设备相关性。

## 3. 导出流程

1. 用户在设置中选择“导出保险库”，通过原生保存目录选择器确定 `.pvault` 目标。
2. 检查当前数据库完整性，锁定会话，复制当前加密数据库和元数据到私有临时目录并同步。
3. 写入最小 manifest 和 ZIP，读取校验包内条目与格式。
4. 原子重命名到目标路径；目标已存在时返回冲突，不覆盖。
5. 临时文件清理，当前保险库回到解锁页。

原生目录选择器取消时不创建文件、不改变当前会话。

## 4. 导入流程

### 4.1 用户确认

- 通过原生文件选择器选择 `.pvault`。
- 明确提示“导入将替换当前保险库”，用户确认后输入**原保险库主密码**。
- 原密码仅用于验证导入数据库，不改为当前密码、不写入日志、不持久化。

### 4.2 包校验

- 只接受预期三个 ZIP 条目，拒绝额外文件、目录、绝对路径、`..`、Zip Slip 和重复条目。
- 限制压缩包大小、条目数量、单项及总解压大小和压缩比，防止 Zip Bomb。
- manifest 必须为支持的 `formatVersion: 1`，且 `createdAt` 可解析。
- 在私有临时目录展开后，使用原主密码 unwrap DEK，打开导入 SQLCipher 数据库并执行完整性检查。

### 4.3 备份与原子替换

1. 锁定当前保险库。
2. 验证成功后，在当前工作区的 `backups/import-<时间与操作 ID>/` 创建加密备份；当前为空库时不需要备份。
3. 将导入的 `vault.db` 和 `vault.meta` 原子切换到当前工作区，保留当前 `config.json` 和存储目录。
4. 返回解锁页，使用原保险库主密码解锁。

任一步骤失败均恢复原数据库与配置，清理临时文件，不留下半导入状态。源 `.pvault` 始终只读，不修改。

## 5. 与目录迁移的关系

- 现有目录迁移继续提供备份、复制、验证、失败回滚和原库保留，行为不变。
- 导入导出是显式跨设备复制，不是同步。
- 同一时间只在一台设备修改，导入后不以源设备继续写入，否则需要人工重新复制，应用不自动解决冲突。

## 6. Tauri 与前端边界

新增受限命令和原生选择器：

```text
storage_choose_export_path() -> string | null
storage_choose_import_path() -> string | null
storage_export_pvault(destination) -> { path }
storage_import_pvault(source, masterPassword) -> StorageLocation
```

- 仅 Rust 读取、创建、验证和替换文件；前端没有任意文件系统权限。
- 设置页提供导入/导出按钮、取消、替换确认、密码输入、处理中、成功和错误状态。
- 不新增网络、shell、HTTP、自动更新或远程资源能力。
- Rust 可增加专用 ZIP 读写依赖，不引入前端插件。

## 7. 错误与安全要求

- 错误密码、损坏 SQLCipher、manifest 不支持、恶意路径和异常压缩包均失败关闭。
- 导入失败时当前库和配置保持不变，已有备份不删除。
- 导出失败时不留下目标半成品或公开临时明文。
- 文件权限沿用私有目录和文件限制。
- 日志不得记录密码、恢复密钥、条目内容或压缩包内敏感数据。

## 8. 测试与验收

### Rust

- 导出→导入往返：条目、收藏、密码历史和原密码/恢复密钥可继续使用。
- 错误密码、缺失条目、额外条目、路径穿越、重复条目、Zip Bomb、损坏 manifest 和损坏数据库。
- 目标导出文件冲突、当前库替换失败回滚、配置不变和备份保留。

### 前端

- 原生选择器取消、替换确认、密码错误、成功、处理中和失败状态。
- Demo 不读写真实 `.pvault` 文件。

### 真实桌面

- 导出到隔离临时目录，在另一目录导入替换，使用原密码解锁并验证标记条目与收藏。
- 完整前端、Rust、Chrome E2E、lint、构建、Clippy 和 macOS 桌面验收。
- 更新 README 与 `docs/development-process.md`，Windows 只标记未实测。

## 9. 验收标准

- 单个 `.pvault` 可跨目录/设备复制，内容无明文条目。
- 导入只在验证成功后替换，当前库有可恢复备份，失败无半导入状态。
- 导入后仍由原主密码和恢复密钥控制，无管理员后门或凭据绕过。
