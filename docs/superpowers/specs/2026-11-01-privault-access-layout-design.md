# Privault 访问页双模式布局设计

日期：2026-11-01  
状态：已确认方向，待实施

## 背景与目标

当前欢迎、创建、解锁和恢复页面共用固定双栏布局。日常解锁只需要一个密码输入框，却仍展示完整的品牌介绍区，导致视觉重心分散；左侧品牌名称和三枚说明标签也存在重复。

本设计采用已确认的方案 A：**欢迎与创建使用精简双栏，解锁与恢复使用专注单栏**。目标是让首次启动保留必要解释，让日常解锁更直接，同时不改变任何安全流程。

## 范围

### 包含

- 为访问页布局增加“精简双栏”和“专注单栏”两种模式。
- 欢迎页和创建保险库两个步骤使用精简双栏。
- 解锁页和恢复访问页使用专注单栏，避免流程切换时布局跳动。
- 调整品牌层级、间距、卡片宽度及窄窗口响应式布局。
- 保留现有浅色、深色主题和全部表单交互。
- 增加布局模式测试，并进行浏览器截图检查。

### 不包含

- 不修改 SQLCipher、主密码、恢复密钥、保存位置或解锁逻辑。
- 不修改保险库工作区、设置或 `.pvault` 导入导出。
- 不恢复已移除的顶部“本地加密存储 · 完全离线”横幅。
- 不增加宣传图片、渐变背景、动画或新的导航功能。
- 不在本次布局任务中改写现有导入入口的业务行为。

## 布局设计

### 精简双栏

适用于 `welcome` 和 `create`：

- 页面内容最大宽度保持约 `1024px`，在大窗口中垂直居中。
- 左侧保留一个品牌组合：`BrandMark` 图标与 `Privault` 名称，不再重复显示 `PRIVAULT` 和大号 `Privault`。
- 左侧主标题为“把重要信息，留在本机。”，下方保留一句简短产品说明。
- 删除“完全离线设计”“Mac · Windows”“本地数据”三枚标签。
- 左右栏保持清晰分隔，间距由当前较大的间隔收紧至约 `48–56px`。
- 右侧卡片宽度约 `400–420px`，保留现有表面色、细边框和表单内容。

### 专注单栏

适用于 `unlock` 和 `recover`：

- 页面仅显示一个约 `400–420px` 宽的内容区，水平、垂直居中。
- 品牌组合位于卡片上方，只出现一次。
- 卡片内保留现有标题、说明、表单、错误信息和主要操作。
- 不显示左侧宣传区、大标题或标签，让首个输入框成为主要视觉焦点。
- 解锁进入恢复、恢复完成返回解锁时保持相同布局，避免内容区左右移动。

## 组件结构

继续使用现有 `AccessLayout`、`AccessFlow`、`UnlockScreen`、`CreateVaultFlow` 和 `RecoverAccessScreen`，不复制两套访问流程。

`AccessLayout` 增加可选布局模式参数：

- `split`：默认模式，输出精简品牌区和右侧表单卡片。
- `focused`：输出居中品牌区和单个表单卡片。

`AccessFlow` 根据当前页面选择模式：`welcome` / `create` 使用 `split`，`unlock` / `recover` 使用 `focused`。表单组件不感知布局模式，也不新增业务状态。

## 响应式与视觉约束

- 大窗口使用上述双栏或单栏布局。
- 窗口不足双栏所需宽度时，双栏自动堆叠为单栏；品牌区紧凑排列在卡片上方，宣传标签不再出现。
- 页面高度不足时仍允许垂直滚动，不裁切恢复密钥、保存位置或错误信息。
- 减少装饰性阴影，主要通过边框、留白和字体层级建立视觉层级。
- 保持现有语义颜色 token，确保浅色与深色模式下的文字、边框和焦点状态可辨识。
- 键盘焦点顺序、密码框自动聚焦和按钮可访问名称保持不变。

## 错误与状态处理

本设计不引入新的异步操作或错误类型。现有创建、解锁、恢复错误继续显示在原表单内；布局组件本身不持有或重置表单状态，既有页面切换和状态生命周期保持不变。加载和忙碌状态继续由现有组件管理。

## 验证

- 单元/集成测试覆盖：`AccessFlow` 在欢迎、创建、解锁和恢复页面选择正确布局模式，原有访问流程测试继续通过。
- 运行前端 lint、测试和 TypeScript/Vite 生产构建。
- 使用浏览器分别检查欢迎、创建、解锁和恢复页面，覆盖浅色与深色主题。
- 至少检查一个桌面宽窗口和一个较窄窗口，确认无横向溢出、表单裁切或布局跳动。
- 本次是布局优化，不以重复运行 macOS 原生 `.pvault` 桌面自动化作为验收前提。

## 完成标准

用户首次进入时能看到精简品牌和创建入口；日常解锁时只看到居中品牌和解锁卡片；从解锁进入恢复再返回时布局稳定；所有既有访问流程、表单校验和安全行为保持不变。
