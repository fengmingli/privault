# Privault 独立收藏与核心字段校验设计

日期：2026-10-31  
状态：设计已获用户认可，待实现

## 1. 目标与范围

1. 将“收藏”从单纯星标和收藏优先排序，升级为侧栏独立功能。
2. 为登录信息、安全笔记、银行卡和证件的核心字段提供前端即时校验与 Rust 最终复核。

不包含：全部字段必填、主密码规则变化、收藏云同步、收藏导入导出、跨设备冲突合并。

## 2. 独立收藏功能

### 2.1 分类与数量

侧栏新增“收藏”分类：

- 显示当前未删除收藏条目的数量。
- 收藏视图只包含 `favorite === true` 的条目。
- 可与搜索词组合筛选；普通“全部项目”和各类型分类行为不变。
- 收藏/取消后，列表、数量和详情星标同步更新。

`Category` 扩展为：

```text
"all" | "favorites" | EntryKind
```

过滤逻辑先处理 `favorites` 专用条件，再处理现有类型条件与搜索文本。

### 2.2 选择与空状态

- 在其他分类取消收藏，当前条目保持选中。
- 在收藏视图取消收藏，条目立即移出列表，并选择下一条可见条目。
- 没有可见收藏条目时显示独立空状态，不与“搜索无结果”混用。
- 删除、撤销、编辑和收藏排序均保留当前行为；撤销删除后收藏状态不丢失。

## 3. 核心字段校验

前端在对应字段下方显示具体错误；Rust 在保存命令中复核，防止绕过前端。长度按 Unicode 码点计算。

### 3.1 登录信息

- 用户名：去除首尾空白后必填，最长 320 码点。
- 密码：必填，最长 4096 码点；不套用主密码强度规则。
- 网站：保持选填及现有长度规则，不新增格式要求。

### 3.2 安全笔记

- 笔记内容：去除首尾空白后必填，最长 10000 码点。
- 备注与其他自定义字段保持现有规则。

### 3.3 银行卡

- 卡号：必填；去除所有空格后为 12–19 位 ASCII 数字，并通过 Luhn 校验。
- 有效期：必填，格式 `MM/YY`，月份为 01–12；按月末判断，不能早于当前年月。
- CVV：必填，3–4 位 ASCII 数字。
- 银行和持卡人保持选填。

### 3.4 证件

- 证件号码：去除首尾空白后必填。
- 签发日期和到期日期：均可为空；填写后必须是有效的 `YYYY-MM-DD` 日期。
- 同时填写时，到期日期不能早于签发日期。
- 证件类型和持有人保持选填。

## 4. 校验架构

- 前端沿用集中条目校验函数，为 `cardNumber`、`cvv`、`body`、`documentNumber`、`username`、`password`、`expiry` 和日期字段返回字段级错误。
- 编辑器按现有字段错误展示方式接入，不仅依赖保存 Toast。
- Rust 在现有条目保存校验入口执行相同核心规则，返回稳定、脱敏的字段错误。
- Luhn 校验与有效期计算使用独立、可单测逻辑；时间相关测试使用固定日期，避免随当前日期变化。
- 演示数据必须继续满足这些规则；不强制迁移或改写已有保险库数据。

## 5. 错误与边界

- 仅由空白字符组成的必填内容视为空。
- 密码不因包含空格而被改写；只在判空时检查空白。
- 卡号允许用户输入空格分组，其他符号直接拒绝。
- 当前月份的有效期仍视为有效，过期月份拒绝。
- 非法输入不会写入 SQLCipher；前端不绕过 Rust 校验。
- 已有条目不满足新规则时仍可查看，只有再次保存时需要修正。

## 6. 测试与验收

### 前端

- 收藏分类数量、过滤、取消后选择与空状态。
- 登录用户名/密码、笔记内容、卡号/Luhn、有效期/CVV、证件号码和日期的接受/拒绝组合。
- 编辑器在正确字段下展示错误，合法输入可正常保存。

### Rust

- 收藏字段持久化行为保持。
- 非法核心字段在保存入口被拒绝，合法条目可重启读取。
- Luhn 边界、空内容、无效/过期日期及 Unicode 长度测试。

### 全量验证

- 完整前端测试、Rust 测试、lint、生产构建和 Chrome E2E。
- macOS 真实桌面闭环，包括收藏/取消、核心字段错误提示、创建、重启和迁移。

## 7. 验收标准

- 用户可从侧栏独立进入收藏视图并管理收藏。
- 核心字段错误在保存前可理解地呈现，直接调用 Rust 也无法绕过。
- 现有收藏、编辑、删除撤销和加密存储行为不回归。
