# Privault 前端 UI 原型设计

- 日期：2026-10-27
- 状态：已确认界面方向，待书面规格审阅
- 目标平台：macOS、Windows
- 本期范围：可运行的桌面端前端 UI 原型

## 1. 产品背景

Privault 是一个面向个人用户的完全离线保险库，用于保存账号密码、安全笔记、银行卡、证件等结构化隐私信息。最终产品将支持 Mac 与 Windows，通过加密迁移包手动迁移数据，不提供云同步、浏览器自动填充或桌面自动填充。

本期只实现前端 UI 和可点击的演示流程，不实现真实加密、数据库或保险库迁移。界面必须持续显示“UI 原型，请勿输入真实密码”的明显提示，防止演示原型被误当作安全产品使用。

## 2. 已确认的产品约束

- 应用自身不连接云端，不加载远程字体、图片、脚本或样式。
- 最终产品通过加密文件在 Mac 与 Windows 之间手动迁移；同一时间只在一台设备修改。
- 不做自动冲突合并；可能覆盖数据时必须警告并保留备份。
- 日常操作以应用内搜索、查看和复制为主，不开发浏览器扩展或系统自动填充。
- 数据类型为账号密码、安全笔记、银行卡、证件、自定义字段和密码历史，不支持附件。
- 最终产品使用主密码和一次性恢复密钥，不接入生物识别。
- 本期技术路线为 Tauri 2、Rust、React、TypeScript；Rust 安全核心不在本期实现。

## 3. 本期目标与非目标

### 3.1 目标

1. 建立可运行的 React + TypeScript 桌面 UI，并能由 Tauri 2 加载。
2. 完成创建保险库、恢复密钥、解锁、恢复访问和保险库主页面的视觉与交互原型。
3. 使用内存演示状态实现搜索、分类过滤、新增、查看、编辑、删除和密码生成。
4. 建立浅色与深色主题、桌面三栏布局、键盘操作和基础无障碍能力。
5. 对未接入的导入、导出和真实安全能力给出明确说明，不伪造成功结果。
6. 为核心 UI 状态、验证规则和主要用户路径建立自动化测试。

### 3.2 非目标

- 不实现 Argon2id、SQLCipher、真实密钥生成或安全内存清零。
- 不读写真实保险库，不持久化用户输入的密码或私密条目；演示新增与编辑只保留在当前页面内存中。
- 不承诺剪贴板定时清空、系统休眠锁定等需要原生能力的安全保证。
- 不实现真实导入导出、自动备份、冲突检测或恢复密钥重置。
- 不实现多保险库、云同步、账号体系、遥测、自动更新、附件或自动填充。
- 不针对手机或平板布局。

## 4. 技术结构

### 4.1 技术栈

- 桌面壳：Tauri 2，仅提供窗口与本地前端加载能力。
- 前端：React、TypeScript、Vite。
- 样式：Tailwind CSS 与语义化设计令牌；组件样式不得绕过设计令牌使用临时颜色。
- 组件：本地构建的 React 组件，可按需使用 shadcn/ui 风格的可访问组件。
- 图标：本地打包的 SVG 图标。
- 测试：Vitest、React Testing Library；构建后执行生产构建验证。

运行时不使用 CDN、远程字体、在线图片或第三方请求。原型中的 UI 不依赖网络可用性。

### 4.2 模块边界

```text
AppShell
├─ PrototypeBanner
├─ AccessFlow
│  ├─ WelcomeScreen
│  ├─ CreateVaultFlow
│  ├─ RecoveryKeyStep
│  ├─ UnlockScreen
│  └─ RecoverAccessScreen
└─ VaultWorkspace
   ├─ VaultSidebar
   ├─ EntryListPane
   ├─ EntryDetailPane
   ├─ EntryEditorDialog
   ├─ PasswordGeneratorDialog
   └─ SettingsDialog

UI state and demo adapter
├─ 顶层访问流程状态
├─ 保险库演示状态与 reducer
├─ 搜索、筛选和表单校验
└─ 仅包含虚构条目的 demo repository
```

界面不得把演示数据写入 localStorage、IndexedDB 或文件。若持久化外观设置，只允许白名单中的非敏感键：主题、自动锁定分钟数、剪贴板倒计时偏好；不得保存密码、恢复密钥、条目内容或搜索词。

Tauri 的 Rust 侧本期不提供保险库命令。前端演示 adapter 与未来安全核心之间保持清晰边界，避免把演示状态设计绑定到 DOM 组件。

## 5. 视觉设计系统

### 5.1 设计方向

采用“原生桌面效率工具 + 克制的安全感”。不使用黑客风、霓虹效果、装饰性渐变、大面积玻璃拟态或无意义插画。

- 主色：深青绿，用于主要操作、选中状态和焦点。
- 中性色：略带暖色的石墨灰，用于背景、边框和文字。
- 警告色：琥珀色，仅用于原型提示、覆盖风险和非阻断警告。
- 危险色：红色，仅用于删除、不可恢复操作和错误。
- 主题：浅色、深色、跟随系统；两种主题都满足可读性要求。
- 字体：macOS 使用系统字体，Windows 使用 Segoe UI；中文回退到 PingFang SC 或 Microsoft YaHei。密码和恢复密钥使用系统等宽字体。
- 间距：以 4px 为基础，主要使用 8、12、16、24、32px。
- 圆角：输入框与按钮 8px，卡片与对话框 12px。
- 动效：120–180ms；仅用于状态过渡，不阻碍操作，尊重减少动态效果设置。

### 5.2 样式约束

所有颜色先定义为 HSL 语义令牌，再映射到组件。至少包含：

- `background`、`surface`、`surface-raised`、`border`
- `foreground`、`foreground-muted`
- `primary`、`primary-foreground`、`primary-hover`
- `accent`、`warning`、`danger`
- `focus-ring`、`selection`

密码强度、类型图标和分类状态不能仅依靠颜色表达，还需文字、图形或辅助标签。

## 6. 页面与状态设计

### 6.1 顶层访问流程

顶层状态为：

```text
welcome → create → recovery-key → vault
   │          │           │
   │          └───────────┴──→ unlock
   ├─→ unlock ──解锁成功──→ vault
   │        └─→ recover-access → unlock
   └─→ import-explainer

vault ──手动或超时锁定──→ unlock
```

原型解锁页明确显示演示密码 `demo`，只接受该值；错误时显示“演示密码不正确”，不得鼓励用户输入真实主密码。

创建与恢复流程只验证界面规则，不创建真实保险库。恢复密钥页面展示明确标记为演示用途的不可用示例，并提供复制、打印样式和“已离线保存”复选框；未确认时不能继续。

### 6.2 保险库主页

以 1280×800 为基准，最小目标窗口为 1024×700。

```text
┌──────────────┬───────────────────┬───────────────────────────────┐
│ Privault     │ 搜索项目…     ＋  │ 条目标题                   ⋯  │
│ 原型状态      ├───────────────────┤ 类型与收藏                    │
│              │                   │                               │
│ 全部项目      │ 条目列表           │ 字段、显示、复制               │
│ 登录信息      │ 标题与摘要         │ 备注与自定义字段               │
│ 安全笔记      │ 更新时间           │ 密码历史                       │
│ 银行卡        │                   │                               │
│ 证件信息      │                   │ 编辑与危险操作                 │
│              │                   │                               │
│ 密码生成器    │                   │                               │
│ 设置          │                   │                               │
│ 立即锁定      │                   │                               │
└──────────────┴───────────────────┴───────────────────────────────┘
```

- 左栏约 216px；窗口较窄时收缩为图标栏，并保留可访问名称。
- 中栏约 320px；窗口较窄时可降至 280px。
- 右栏占据剩余空间，内容超出时独立滚动。
- 顶部始终提供搜索、新建和锁定入口。
- 空保险库、无搜索结果和未选择条目使用不同的空状态，不使用灰色占位块。

### 6.3 条目类型

所有类型共用标题、收藏、备注、自定义字段、创建时间和更新时间。

- 登录信息：用户名、密码、网站、密码历史。
- 安全笔记：多行正文。
- 银行卡：持卡人、卡号、有效期、安全码、发卡行；演示数据只使用明显虚构值。
- 证件：证件类型、持有人、证件号码、签发日期、到期日期。
- 自定义字段：文本、密码、日期；支持新增、编辑和删除。

首版不提供 TOTP、附件、关系字段或自定义条目类型。

### 6.4 新增与编辑

- 点击“新建”先选择类型，再打开对应表单。
- 编辑以对话框或右侧覆盖层呈现，保持当前列表上下文。
- 必填项、日期、字段长度和重复自定义字段名称在本地校验。
- 密码字段默认遮挡，可显示、复制并打开密码生成器。
- 从生成器选择“填入”后，只更新当前编辑表单，不自动保存。
- 关闭存在未保存修改的表单时必须确认。
- 删除条目必须显示标题并要求二次确认；演示状态删除后可撤销。

### 6.5 密码生成器

- 支持长度 12–64，默认 20。
- 支持大写、小写、数字、符号和排除易混淆字符。
- 至少保留一种字符组；无效组合显示内联错误。
- 提供本地强度说明、重新生成、复制和“填入当前表单”。
- 演示原型可使用浏览器加密随机数接口生成演示密码，但不得将此描述为完整的安全核心实现。

### 6.6 设置

设置分为三组：

- 外观：浅色、深色、跟随系统。
- 锁定与剪贴板：自动锁定时间、复制后倒计时偏好。
- 数据：导入、导出和迁移说明。

原型的手动锁定和基于界面空闲时间的自动锁定可以实际操作。系统休眠锁定、原生安全剪贴板和真实数据迁移显示“待接入安全核心”，不得展示虚假的成功提示。

## 7. 演示数据与交互行为

### 7.1 演示数据

内置少量完全虚构的登录、笔记、银行卡和证件条目，覆盖：

- 有网站和无网站的登录条目。
- 有密码历史的条目。
- 长标题、长用户名和多行备注。
- 收藏与非收藏条目。
- 空分类与空搜索结果。

演示数据在每次重新加载时复位，不持久化用户编辑。

### 7.2 搜索与排序

- 搜索匹配标题、用户名、网站和备注。
- 搜索词只保存在内存中，锁定或离开主页时清除。
- 支持按分类过滤，并按收藏优先、最近更新排序。
- 搜索与过滤可以组合；无结果时提供清除搜索和过滤的操作。

### 7.3 复制与通知

- 对演示字段调用可用的剪贴板 API，成功或失败都必须给出真实反馈。
- 通知不拼接完整私密字段，只显示“用户名已复制”或“密码已复制”。
- 原型不保证操作系统级定时清空；设置页明确标注该限制。
- 同时只显示一个短时通知，重要错误保留到用户处理。

### 7.4 键盘与焦点

- `Cmd/Ctrl + K`：聚焦搜索。
- `Cmd/Ctrl + N`：新建条目。
- `Cmd/Ctrl + Shift + L`：立即锁定。
- `Escape`：关闭最上层对话框；有未保存修改时先确认。
- 所有功能均可通过键盘完成，不将快捷键作为唯一入口。
- 对话框打开后管理焦点，关闭后返回触发按钮；焦点状态清晰可见。

## 8. 错误与边界处理

- 空密码、两次密码不一致、无效恢复密钥格式：在字段附近显示错误。
- 错误演示密码：不清空其他无关界面状态，不记录输入内容。
- 空列表、无搜索结果、空分类：提供针对性下一步操作。
- 剪贴板不可用：显示失败提示，不伪造成功。
- 未保存修改：关闭表单或切换条目时提供“继续编辑 / 放弃修改”；手动锁定时明确提示未保存修改将被放弃。自动锁定不保留草稿，直接进入解锁页并清除表单、搜索词和已显示密码。
- 导入导出：只打开能力说明，不选择或写入真实文件。
- 窗口宽度不足：优先保留列表和详情操作，左栏收缩，不产生横向页面滚动。
- 原生能力不可用：界面仍可浏览和操作演示数据。

## 9. 测试与验收

### 9.1 自动化测试

至少覆盖：

1. 演示解锁成功与失败。
2. 创建流程的密码匹配和恢复密钥确认。
3. 搜索、分类过滤和清空过滤。
4. 新增、编辑、取消未保存修改、删除和撤销。
5. 密码生成器长度、字符组校验和填入表单。
6. 密码显示、复制成功与复制失败反馈。
7. 手动锁定、自动锁定状态转换和敏感 UI 状态清理。
8. 主题切换及设置白名单持久化。

### 9.2 视觉与人工验收

- 在 1280×800 和 1024×700 下检查三栏布局、滚动和对话框。
- 分别检查浅色与深色主题，正文对比度至少 4.5:1。
- 完成“解锁 → 搜索 → 查看 → 编辑 → 保存 → 复制 → 锁定”完整路径。
- 完成“新建 → 生成密码 → 填入 → 保存 → 删除 → 撤销”路径。
- 检查空输入、错误演示密码、无搜索结果和剪贴板失败路径。
- 仅用键盘完成主要路径，检查焦点顺序与焦点恢复。
- 检查生产构建和浏览器控制台，无运行时错误或远程资源请求。

### 9.3 完成标准

当主要页面和状态均已实现、核心交互可操作、自动化测试通过、生产构建成功，并且所有安全相关占位能力都有明确标识时，本期 UI 原型完成。它不代表 Privault 已具备保存真实隐私数据的安全能力。

## 10. 后续衔接

UI 原型审阅完成后，再分别设计并实现：

1. Rust 保险库与密钥管理核心。
2. SQLCipher 存储和真实数据 adapter。
3. 加密迁移包、备份与覆盖保护。
4. 原生剪贴板、系统休眠锁定及 Mac / Windows 发布验证。

每个后续阶段都需要独立的安全设计与验证，不能通过简单替换演示 adapter 默认继承其安全性。
