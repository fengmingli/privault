# 欢迎页 `.pvault` 导入设计

日期：2026-11-01  
状态：已确认，待实施

## 目标

欢迎页“导入已有保险库”接入现有真实 `.pvault` 导入能力，移除“本期不支持导入或导出”的过期提示。用户选择加密文件并验证原主密码后，可以返回解锁页使用原凭据解锁。

## 用户流程

- 真实模式欢迎页点击“导入已有保险库”，打开现有 `PvaultDialog` 的导入模式。
- 通过 Rust 原生选择器选择 `.pvault`，输入原保险库主密码并确认。
- 继续复用现有严格归档检查、SQLCipher 完整性验证、已有库备份和失败回滚。
- 成功后保留“返回解锁”操作，点击后切换到现有解锁页，不自动解锁或跳过密码验证。
- 浏览器 Demo 仍只显示“不支持真实文件操作”的说明，不调用选择器或写入文件。
- 导出仍只在解锁后的设置中提供，不在欢迎页增加导出入口。

## 状态与安全规则

`VaultManager::import_pvault` 允许从 `Empty`、`Locked` 和 `Unlocked` 状态进入。导入开始时仍先锁定当前会话，整个验证和替换流程不变。

- 从 `Empty` 导入成功后，会话必须变为 `Locked`，否则现有 `unlock` 会因 `Empty` 状态拒绝解锁已经导入的文件。
- 从 `Locked` 或 `Unlocked` 导入成功后，会话保持或回到 `Locked`。
- 导入失败时保留原会话状态和原保险库文件；已有回滚逻辑不变。
- 原保险库主密码只用于验证和解包导入文件，不写入配置或日志。
- 已有保险库仍写入 `backups/import-*`；空工作区没有原库时不创建虚假备份成功承诺。

## 对话框文案

现有对话框同时服务空库和已有库，文案改为通用表述：

- 初始说明：选择要导入当前位置的 `.pvault` 文件，验证原主密码后才会写入。
- 确认标题：“导入到当前保险库位置”。
- 确认说明：“如果当前位置已有保险库，验证成功后会先自动备份再替换。导入后请使用原保险库主密码解锁。”
- 主按钮：“确认导入”。
- 成功状态：“导入完成”，不再固定显示“原保险库已备份”。

这些修改只调整表述，不改变备份和回滚行为。

## 组件改动

- `AccessFlow` 用导入对话框打开状态替代 `importNotice`；欢迎页按钮打开对话框。
- `PvaultDialog` 继续通过现有 `VaultGateway` 调用，不新增 Tauri 命令或前端文件权限。
- 导入忙碌状态继续通过 `onBusyChange` 暴露，欢迎页操作在忙碌时禁用。
- `onRequireUnlock` 关闭对话框并切换到 `unlock`，不调用 `onUnlocked`。

## 验证

- Rust：分别从空状态和锁定状态导入，随后用原主密码解锁并核对标记条目。
- 既有 Rust 错误密码、损坏包、恶意路径和替换失败回滚测试继续通过。
- 前端：欢迎页不再显示过期提示，真实模式打开导入对话框，成功后进入解锁页；Demo 不执行真实操作。
- 前端：对话框通用文案与成功状态测试更新。
- 运行 Rust 测试、前端 lint/测试/构建和 Chrome E2E；本任务不重复运行 macOS 原生桌面自动化。

## 非目标

- 不实现条目合并、冲突解决、云同步或自动解锁。
- 不改变 `.pvault` 文件格式、密钥槽或备份目录结构。
- 不在欢迎页增加导出、附件或新的文件系统权限。
