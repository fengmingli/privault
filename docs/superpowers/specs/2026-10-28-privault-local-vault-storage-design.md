# Privault 本地加密保险库与存储路径设计

- 日期：2026-10-28
- 状态：已于 2026-10-28 完成书面规格审阅并确认
- 目标平台：macOS、Windows
- 本期范围：真实单机加密保险库、固定磁盘路径配置与自动迁移

## 1. 背景

Privault 的前端 UI 原型已完成，但演示条目只存在于内存中，不能用于真实隐私数据。本期将把 UI 原型升级为真实单机应用：用户可以创建和解锁保险库，保存结构化条目，并在设置中选择本机固定磁盘上的存储目录。更改目录时，应用自动备份、复制、验证并切换现有保险库。

应用不连接云端，不提供网络同步。所有私人数据落盘前必须由 Rust 安全核心加密，前端不得直接访问数据库或获得任意文件系统权限。

## 2. 已确认的需求

- 使用 Tauri 2、Rust、React 和 TypeScript。
- 使用 SQLCipher 加密本地 SQLite 数据库，采用 `vault.db` 与 `vault.meta` 工作区。
- 主密码和一次性恢复密钥分别封装同一个随机 DEK，不接入生物识别。
- 存储路径可在设置中修改，且只能位于本机固定磁盘。
- 默认禁止网络盘、NAS、SMB 和 U 盘等可移动磁盘。
- 修改路径采用自动迁移：备份、复制、验证成功后才切换；原位置保留加密备份。
- 目标目录存在同名保险库时停止，不覆盖、不合并。
- 本期完成创建、解锁、条目增删改查、软删除撤销、主密码修改、恢复密钥重置和路径迁移。
- 跨设备 `.pvault` 导入导出、原生剪贴板清理、系统休眠锁定和安装包发布不属于本期。
- 现有演示数据不得写入真实保险库；真实保险库从空数据开始。

## 4. 总体架构

```text
React 设置页与保险库界面
          │ 类型安全 vault-client
          ▼
Tauri commands（输入校验、串行执行、脱敏错误）
          │
┌─────────┼───────────┐
▼         ▼           ▼
Vault    Crypto      Config
Session  密钥槽       非敏感路径配置
          │
       Storage
       SQLCipher
          │
    PathPolicy + Migration
```

### 4.1 Rust 模块

- `vault/`：保险库创建、解锁、锁定、会话和条目用例。
- `crypto/`：DEK、Argon2id、密钥封装、恢复密钥和内存清零。
- `storage/`：SQLCipher 连接、数据库迁移、事务和查询。
- `metadata/`：元数据解析、认证和原子写入。
- `config/`：应用配置、默认路径和当前存储位置。
- `path_policy/`：固定卷、链接、权限、空间和目标冲突校验。
- `migration/`：备份、临时副本、目标验证和路径提交。
- `commands/`：Tauri DTO、锁定检查、会话串行化和脱敏错误。

前端只能通过 `src/lib/vault-client.ts` 调用类型安全命令。React 不执行 SQL、不派生密钥、不处理原始数据库路径，也不直接读取或写入保险库文件。

## 5. 文件与目录

### 5.1 默认位置

保险库默认目录：

- macOS：`~/Library/Application Support/Privault/`
- Windows：`%LOCALAPPDATA%\Privault\`

应用配置文件始终保存在上述默认目录，名称为 `config.json`。即使用户把保险库移动到其他固定磁盘目录，应用仍能从默认配置找到它。配置文件只包含格式版本和存储路径，不包含密码、恢复密钥或条目。

### 5.2 保险库工作区

```text
<固定磁盘存储目录>/
├── vault.db
├── vault.meta
└── backups/
    └── migration-<UTC 时间与操作 ID>/
        ├── vault.db
        └── vault.meta
```

- `vault.db`：SQLCipher 密文数据库。
- `vault.meta`：格式版本、保险库 ID、算法版本、KDF 参数、盐值、Nonce 和封装密钥槽。
- `backups/`：路径迁移前的加密副本，不包含明文。
- 原始目录中的文件在本期不删除，即使目标验证成功也保留。

`vault.meta` 是解锁必需文件，不包含标题、账号等私人内容，但必须与数据库一起复制和备份。数据库与元数据版本不匹配时拒绝解锁。

### 5.3 文件权限

- macOS：保险库目录权限 `0700`，数据库、元数据、配置和备份文件权限 `0600`。
- Windows：目录和文件 ACL 只允许当前用户访问，不继承不必要的共享权限。
- 临时文件使用唯一名称，并在成功后原子重命名；临时内容仍为密文或非敏感配置。

## 6. 密钥与密码流程

### 6.1 密钥模型

创建保险库时由操作系统 CSPRNG 生成 256 位 DEK。SQLCipher 直接使用该 DEK 的原始密钥材料，不把 DEK 写入元数据。

```text
主密码 ──Argon2id + 独立盐──→ 主密钥 KEK ─┐
                                           ├─ 分别封装同一个 DEK
恢复密钥 ──独立 KDF 参数────→ 恢复 KEK ───┘
```

- 主密码至少 12 位，并提供本地强度提示。
- Argon2id 参数在创建时按设备性能校准，目标解锁耗时约 500ms，并与盐值、算法版本一起存储。
- 恢复密钥至少包含 256 位随机熵，使用带校验位的分组 Base32 编码，防止录入错误。
- 密钥封装采用 XChaCha20-Poly1305；AAD 包含格式版本、保险库 ID、密钥槽 ID、算法版本和 KDF 参数。
- DEK 和 KEK 只存在于 Rust 受控内存中，使用具备清零能力的容器管理。

### 6.2 创建与解锁

1. 应用确认目标目录不存在已有保险库。
2. 生成 DEK、保险库 ID 和两个独立密钥槽。
3. 创建元数据和 SQLCipher 数据库，提交初始化事务。
4. 返回一次性恢复密钥，要求用户确认已离线保存。
5. 解锁时选择主密码或恢复密钥槽，派生 KEK 并解封 DEK。
6. 解封成功后打开 SQLCipher；失败时不创建会话。
7. 锁定时关闭数据库、清空前端敏感状态并清零密钥材料。

错误凭据与无法认证的数据不向用户返回可区分的密码学细节，只显示“无法解锁，请检查凭据或保险库完整性”。

### 6.3 修改与恢复

- 修改主密码需要当前主密码，成功后原子替换主密钥槽，数据库不变。
- 恢复访问使用恢复密钥解封 DEK，设置新主密码并生成新的恢复密钥。
- 新元数据通过同目录临时文件、同步和原子重命名写入；旧元数据保留为加密备份。
- 恢复完成后旧恢复密钥失效，新恢复密钥只显示一次。

## 7. 数据库与条目操作

### 7.1 逻辑结构

`entries` 保存公共字段和类型负载：

- `id`、`kind`、`title`、`favorite`、`notes`
- `payload_json`：登录、笔记、银行卡或证件的专属字段
- `created_at`、`updated_at`、`deleted_at`
- `revision`

关联表：

- `custom_fields`：`entry_id`、`id`、`label`、`kind`、`value`、`position`
- `password_history`：`entry_id`、`id`、`password`、`changed_at`
- `schema_migrations`：数据库结构版本和迁移时间

数据库由 SQLCipher 整库加密。搜索由 Rust 读取当前保险库条目后执行，匹配标题、用户名、网站、备注和笔记正文；列表只向前端返回摘要，完整密码仅在选中条目时读取。

### 7.2 写入规则

- 所有写入使用参数化查询和事务。
- 每次成功修改递增保险库修订号，为后续跨设备冲突检测保留基础。
- 登录密码变化时，把旧密码写入 `password_history`；未变化时不重复记录。
- 自定义字段名称在同一条目内必须非空、长度不超过 40 且忽略大小写后不重复；字段值不超过 4000 字符。
- 标题必填且不超过 120 字符，备注不超过 10000 字符，银行卡有效期使用 `MM/YY`，证件到期日不能早于签发日。
- 删除设置 `deleted_at`，普通查询不返回已删除条目；撤销清除 `deleted_at`。
- 锁定时不得存在未提交的写事务，冲突时以最后一次已完成事务为准，不自动合并并发编辑。

数据库启用外键、`secure_delete`、内存临时库和完整同步，不使用 WAL。实现必须验证回滚日志及临时文件不包含敏感明文。

## 8. 存储路径策略

前端传入的候选路径不能直接信任。Rust 必须：

1. 规范化绝对路径，并解析已有路径组件中的符号链接或 Windows reparse point。
2. 拒绝文件系统根目录、无权限目录和无法创建目录的路径。
3. macOS 验证目标为本地卷；Windows 验证目标卷为 `DRIVE_FIXED`。
4. 拒绝网络盘、可移动磁盘和链接逃逸到其他卷的路径。
5. 检查目标可写，并要求可用空间至少为当前工作区与迁移备份总大小的两倍。
6. 若目标已有 `vault.db` 或 `vault.meta`，返回路径冲突，不覆盖、不合并。
7. 只创建或修改明确命名的保险库文件，不删除目录中的其他文件。

如果启动时配置目录不可用，应用显示错误，不静默回退默认目录，也不在错误位置创建新保险库。

## 9. 自动路径迁移

### 9.1 两阶段流程

**准备阶段 `storage_prepare_migration`**

1. 检查当前没有未保存编辑、其他写入或迁移操作。
2. 锁定界面、关闭数据库并清除当前会话密钥。
3. 在原目录 `backups/migration-<时间与操作 ID>/` 创建加密备份。
4. 将工作区复制到目标目录的唯一临时文件，执行文件和目录同步。
5. 返回 `migrationId`，原路径配置保持不变。

**确认阶段 `storage_confirm_migration`**

1. 用户输入主密码。
2. 使用目标临时副本验证密码、元数据、SQLCipher 完整性和条目读取。
3. 验证失败时删除本次创建的临时文件，保留原配置并返回错误。
4. 验证成功后，将临时文件原子重命名为正式文件并同步目录。
5. 原子更新 `config.json` 中的存储路径。
6. 清除迁移用密钥，返回解锁页；从新目录解锁后才能继续编辑。

用户取消时调用 `storage_cancel_migration`，只清理本次创建的临时文件，原配置和原始保险库不变。

### 9.2 失败与崩溃语义

- 密码错误、权限不足、空间不足或目标冲突：不修改当前保险库或配置。
- 备份失败：在复制目标前停止，原目录不变。
- 复制、完整性校验或同步失败：清理本次临时文件，继续使用原目录。
- 目标重命名或配置写入失败：保留原配置；仅清理能够确认属于本次操作的文件。
- 配置写入前崩溃：下次启动仍使用完整的原库；目标可能保留加密副本，不自动删除无法确认归属的文件。
- 配置写入后崩溃：目标已经完成验证，下次启动使用新目录。
- 元数据与数据库不匹配：拒绝解锁并提示存在加密备份，不自动修复或覆盖。

配置更新始终是最后一步，因此不会把应用指向半写入副本。任何错误都不得导致原库和加密备份同时不可用。

## 10. Tauri 命令接口

```text
vault_create(masterPassword) -> { recoveryKey }
vault_unlock(password) -> VaultStatus
vault_lock() -> void
vault_status() -> VaultStatus
vault_list_entries() -> EntrySummary[]
vault_get_entry(id) -> VaultEntry
vault_upsert_entry(entry) -> VaultEntry
vault_delete_entry(id) -> void
vault_restore_entry(id) -> void
vault_change_master_password(currentPassword, newPassword) -> void
vault_recover_access(recoveryKey, newMasterPassword) -> { recoveryKey }

storage_get_location() -> StorageLocation
storage_choose_location() -> string | null
storage_prepare_migration(destination: string | null) -> { migrationId }
storage_confirm_migration(migrationId, masterPassword) -> StorageLocation
storage_cancel_migration(migrationId) -> void
```

- 每个命令在 Rust 侧验证参数和会话状态。
- 所有写入和迁移通过同一个会话互斥锁串行执行。
- 锁定后，条目与修改类命令返回 `LOCKED`；创建、解锁、恢复访问和存储位置流程按各自状态机处理。
- 原生目录选择由 Rust 打开；取消返回 `null`，不改变路径。
- 前端错误只包含稳定错误码和脱敏消息，不返回 SQL、堆栈、密钥或密码学内部细节。

错误码至少包括：`LOCKED`、`INVALID_CREDENTIALS`、`VAULT_NOT_FOUND`、`VAULT_ALREADY_EXISTS`、`VAULT_CORRUPT`、`PATH_UNSUPPORTED`、`PATH_CONFLICT`、`PATH_UNAVAILABLE`、`INSUFFICIENT_SPACE`、`MIGRATION_IN_PROGRESS`、`MIGRATION_NOT_FOUND` 和 `IO_ERROR`。

## 11. 设置页与前端行为

“数据”区域新增“存储位置”卡片：

```text
存储位置
<当前规范化路径>
本机固定磁盘 · 加密存储

[更改存储目录]  [恢复默认目录]
```

- 只通过系统目录选择器修改，不提供可粘贴任意路径的文本框。
- 恢复默认目录使用相同的备份、验证和回滚流程。
- 恢复默认目录时前端传 `destination: null`，默认路径只由 Rust 计算；前端不拼接用户主目录或应用数据路径。
- 迁移中显示备份、复制、验证和切换阶段，并禁止编辑、删除和其他迁移。
- 成功后提示“存储位置已更新，请重新解锁”。
- 失败时显示脱敏原因，当前路径保持不变。
- 启动路径不可用时提供明确的恢复选择，不静默创建新库。
- 主题、自动锁定和剪贴板偏好继续使用现有非敏感设置；真实存储路径只能由 Rust 配置管理。

真实数据适配器通过 `vault-client` 替换演示数据源。只有真实创建、重启、解锁和路径迁移闭环全部通过后，才移除“UI 原型”提示；演示数据不得导入真实保险库。

## 12. 安全边界

本设计防御设备或文件丢失、数据库被复制、离线文件分析和意外路径切换导致的数据丢失。它不能防御已解锁设备上的恶意软件、键盘记录器、被攻陷的操作系统或用户对明文界面的直接观察。

不得在主密码、恢复密钥、密码字段、日志、崩溃信息和错误堆栈之间建立持久记录。前端通知不得包含被复制的完整秘密值。
